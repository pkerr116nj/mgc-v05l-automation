# Track B Trading Stack Handoff Contract

Status: required contract for broker-backed Track B PAPER execution

Scope: Track B strategy decision, paper submit, broker-backed fill evidence, lifecycle ownership, managed exits, reconciliation, operator status, and notifications.

This contract defines what each layer must hand to the next layer so identity, authority, and broker-backed truth are preserved end-to-end. It is ticker agnostic. The same rules apply to MNQ, MES, MGC, GC, agriculture futures, crypto products, and future instruments.

## Global Invariants

- PAPER only unless a separate live-money constitution explicitly replaces this contract.
- `live_money_eligible=false` is required.
- `paper_proof_invoked=false` is required.
- Notifications are advisory only and never trading authority.
- Broker mutation is allowed only through the guarded PAPER broker bridge after all hard gates pass.
- Local artifacts can describe intent, but they cannot prove submit, fill, position, or close.
- Broker-backed fill evidence requires broker-sourced identifiers where available: `order_id`, `client_id`, `perm_id`, and `exec_id`.
- Managed closes must use exact lifecycle owner identity. Aggregate placeholders such as `MULTIPLE`, `MISSING`, `UNKNOWN`, or blank values cannot block an exact lifecycle close when the broker-backed lifecycle row resolves the account and contract identity.
- True mismatches remain hard blockers: non-owner close, qty mismatch, account mismatch, `conId` mismatch, `localSymbol` mismatch, missing lifecycle identity, stale broker truth, or unreconciled lifecycle truth.
- Safe-State submit authority is distinct from runtime-start authority. A runtime may be allowed to start while submit remains blocked.
- Contract resolver applies to new entries only. Managed exits must use the original filled contract identity.

## Freshness Requirements

Unless a narrower policy exists, these artifacts must be fresh at submit/exit time:

- Canonical runtime readiness: fresh enough to represent the active runtime generation.
- Paper runtime truth: fresh and single-writer.
- Broker truth: fresh positions and open orders from broker read-only refresh.
- Broker/lifecycle reconciliation: fresh and clean.
- Control Plane Snapshot: fresh and submit-compatible.
- Safe-State envelope: fresh and `submit_allowed=true` for submit paths.
- Route health: fresh for the selected lane and broker adapter.
- Contract details: fresh for new entries.

Stale, missing, ambiguous, or conflicting authority fails closed.

## Handoff Matrix

### 1. Strategy Signal to PositionIntent

Required fields:

- `runtime_generation_id`
- `source_component`
- `source_artifact_path`
- `lane_id`
- signal timestamp
- `symbol`
- `side`
- `action`
- `qty`
- evidence summary sufficient for replay

Optional fields:

- `signal_id`
- reference prices
- bar timestamps
- session labels
- feature values
- diagnostic fail/pass reasons

Canonical authority source:

- Strategy runtime evaluation artifact for the current runtime generation.

Fail-closed conditions:

- Missing `lane_id`, `symbol`, side/action, or qty.
- Signal artifact stale for the runtime generation.
- Signal depends on stale UI/backend state instead of canonical runtime or market-data artifacts.
- Strategy is outside its eligible session/window.

Diagnostic artifacts:

- Runtime evaluation log.
- Strategy lane evaluation artifact.
- No-trade diagnostics.

Forbidden inference:

- Do not infer a signal from operator UI status.
- Do not infer signal freshness from file modification time alone when the artifact has a generated timestamp.

Tests required:

- Signal with all required identity fields creates a valid PositionIntent.
- Missing `lane_id`, side/action, qty, or stale source artifact fails closed.
- Out-of-window signal does not create submit-capable intent.

## Required Cross-Layer Test Suites

- Identity propagation: signal through lifecycle close preserves `lane_id`, thesis `strategy_id`, `lifecycle_id`, account, contract, qty, and broker evidence ids.
- Authority separation: runtime-start allowed does not imply submit allowed.
- Broker-backed evidence: local artifacts cannot imply fills, closes, or lifecycle ownership.
- Managed close exact identity: exact lifecycle row wins over aggregate placeholders; true mismatches block.
- Contract resolver split: new entries use resolver; managed exits use original filled contract.
- Staleness: stale readiness, broker truth, Safe-State, Control Plane, route health, or reconciliation blocks submit.
- Ticker agnosticism: representative fixtures include index futures, metals, agriculture futures, and crypto-like symbols.
